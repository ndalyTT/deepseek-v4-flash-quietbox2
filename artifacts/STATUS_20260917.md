### Plan for question 2

`terminal_bench_2_1/run_cust901_intermittency_check.sh` (new, not yet run)
performs exactly the sequence Aaron asked for, serialized and bounded:

1. Refuse to start if any TT workload process or any `tt-model-*` container
   is present, or if `tt-smi -ls --local` does not show four devices.
2. Record `tt-smi -s`, firmware version, tt-metal commit and worktree status.
3. Run the Aug 31 fabric smoke (`EXACT_COMMAND.sh` semantics) N times
   (default 3) with no reset between runs. Stop at the first non-pass.
4. Immediately launch the unchanged DeepSeek harness server
   (`run_deepseek_v4_harness_server.sh`) under `script`, wait up to 45 min
   for `/health` on 127.0.0.1:8010, and stop early on the known failure
   signatures.
5. On failure: wait for the process to exit, take a post-failure
   `tt-smi -ls`, bundle logs with a SHA-256 manifest for the ticket. On
   success: leave the server running for the v27 canary, record `/v1/models`.

It does not reset, flash, or loop.
